# סוכן מאמן לצ'אטבוט וואטסאפ — אזרחות ודרכון רומני

מערכת שמריצה סימולציות של לידים אמיתיים מול הצ'אטבוט של המשרד, שומרת תמליל,
ומחזירה דוח איכות עם ציון ונקודות לשיפור.

**איך זה עובד:** סוכן מבוסס Claude מתחזה ללקוח שפונה בוואטסאפ. ההודעה שלו נשלחת
לפונקציה `send_to_my_bot(message)`, תשובת הבוט חוזרת אליו, והוא ממשיך את השיחה —
עד שהוא מרגיש שהשיג את מטרתו או עד מכסת התורות. בסוף, סוכן מעריך קורא את התמליל
ומחזיר דוח.

---

## התקנה מהירה

```bash
pip install -r requirements.txt
cp .env.example .env          # ואז ערוך את .env והכנס ANTHROPIC_API_KEY
```

בדיקה שהכל מחובר, בלי לשרוף טוקנים ובלי מפתח:

```bash
python run_training.py --dry-run --persona avi_impatient --turns 6
```

הרצה אמיתית — כל הפרסונות ברצף ודוח מסכם:

```bash
python run_training.py
```

|---|---|
| `python run_training.py` | כל 8 הפרסונות ברצף + דוח מסכם משווה |
| `python run_training.py --persona avi_impatient` | פרסונה אחת |

| `python run_training.py --random --runs 5` | 5 שיחות עם פרסונות אקראיות |
| `python run_training.py --turns 6` | הגבלת מכסת התורות (ברירת מחדל: 10) |
| `python run_training.py --list` | רשימת הפרסונות |
| `python run_training.py --bot prompt` | להריץ מול הפרומפט שלך מ-`knowledge/my_bot_prompt.md` |
| `python run_training.py --bot manual` | מצב ידני — אתה מדביק את תשובות הבוט |
| `python run_training.py --dry-run` | בדיקת צנרת בלי קריאות API |
| `python run_training.py --no-eval` | סימולציה בלבד, בלי הערכה |
| `python run_training.py --quiet` | בלי הדפסת השיחה בזמן אמת |

הפלטים נשמרים תחת `runs/`:

```
runs/transcripts/<run_id>.json    התמליל המלא + מטא-דאטה
runs/reports/<run_id>.json/.md    דוח לכל סימולציה
runs/summaries/summary_*.md       דוח מסכם לסבב
```

תוכל לראות דוגמאות פלט מוכנות בתיקיית `examples/`.

## מול מה המערכת רצה — ארבעה מצבים

| מצב | מתי | איך מפעילים |
|---|---|---|
| `prompt` | **הבוט עדיין לא באוויר, אבל יש לך את הפרומפט שלו** | הדבק את הפרומפט ל-`knowledge/my_bot_prompt.md` — המערכת עוברת אליו לבד |
| `real` | הבוט חי ויש לו endpoint | הגדר `MY_BOT_ENDPOINT` ב-`.env` |
| `manual` | הבוט חי בממשק סגור (ManyChat / n8n / Make) בלי API נגיש | `--bot manual` — המערכת מדפיסה כל הודעה, אתה מדביק את תשובת הבוט |
| `mock` | סתם להתרשם מהמערכת | ברירת מחדל כשאין כלום — בוט דמה כללי עם חולשות מובנות |

ברירת המחדל היא זיהוי אוטומטי לפי הסדר: endpoint ← פרומפט ← דמה. אפשר לכפות
מצב עם `--bot real|prompt|manual|mock`.

### אימון הפרומפט לפני שהבוט באוויר (מצב `prompt`)

זה השימוש העיקרי בשלב הפיתוח: הפרומפט של הבוט שלך רץ מול Claude, הסוכן המאמן
מתעמת איתו, והדוח אומר לך מה לתקן — לפני שלקוח אמיתי פוגש אותו.

```bash
# 1. הדבק את הפרומפט של הבוט לתוך knowledge/my_bot_prompt.md
# 2. הרץ
python run_training.py --bot prompt
# 3. קרא את הדוח המסכם, תקן את הפרומפט, הרץ שוב
```

מגבלה שכדאי להכיר: מצב זה בודק את **הפרומפט** — הטון, ההיגיון, ההתמודדות עם
לחץ, ההזיות. הוא לא בודק את התשתית סביבו (RAG, כפתורים, אינטגרציות, זיכרון בין
שיחות). את אלה תבדוק במצב `real` אחרי העלייה לאוויר.

### חיבור הבוט האמיתי (מצב `real`)

הנקודה היחידה לשינוי היא `bot_connector.py`:

- ברירת המחדל שולחת POST עם JSON
  (`{"message": ..., "session_id": ..., "channel": "whatsapp"}`) וקוראת את התשובה
  מהשדה `reply` / `message` / `text` / `response`.
- אם ה-API של הבוט שלך בנוי אחרת — התאם את הפונקציה `_call_real_bot`. שאר הקוד
  לא משתנה.

## מנגנון העצירה

השיחה נעצרת באחד משלושה מצבים:

1. **הסוכן החליט שהמטרה הושגה** — הוא פולט את הסימון `[[סוף_שיחה]]` בסוף הודעתו
   (הסימון מוסר מהתמליל, לא נשלח לבוט). לא יכול לקרות לפני התור הרביעי.
2. **מכסת התורות** — ברירת מחדל 10, ניתן לשינוי ב-`--turns`.
3. **שגיאה מהבוט** — נרשמת בתמליל תחת `stop_reason`.

## מודול הפידבק

בסיום כל סימולציה, סוכן מעריך קורא את התמליל ומחזיר דוח עם:

**שלוש שאלות המפתח שביקשת:**

1. **האם הבוט שמר על שפה מקצועית?** — כן / חלקית / לא, עם ציטוט. נמדד גם מול
   לקוח תוקפני וקטנוני: האם נשאר מכבד בלי להתגונן ובלי להתחנף.
2. **האם הצליח להניע לפעולה?** — "נשמח לעמוד לרשותך" **לא** נחשב. הנעה לפעולה =
   צעד הבא קונקרטי + בקשת פרט מזהה או מועד.
3. **האם הזה עובדות?** — כל טענה עם ציטוט, הסבר למה היא לא מאומתת, ורמת חומרה.

**בנוסף:** ציון כולל 0-100, ציון 1-10 בשמונה ממדים (שפה מקצועית, הנעה לפעולה,
דיוק עובדתי, טיפול בהתנגדויות, איסוף פרטים, בהירות ותמציתיות, שמירה על גבולות,
אמפתיה וטון), אמירות אסורות שנאמרו, איך טופלה שאלת המחיר, מה עבד טוב, נקודות
לשיפור לפי עדיפות, הזדמנויות שהוחמצו, ושורות קונקרטיות להוסיף לפרומפט של הבוט.

הדוח המסכם של סבב מציג טבלה משווה בין הפרסונות, ממוצע לכל ממד, כל הליקויים
לפי עדיפות, וכל ההזיות במקום אחד.

## ⚠️ קובץ מקור האמת — הדבר הראשון למלא

`knowledge/facts.md` הוא הקובץ שמולו נבדקות ההזיות. **כרגע הוא תבנית עם
מקומות ריקים.** כל עוד לא מילאת אותו, המעריך יסמן כמעט כל מספר שהבוט אומר
כטענה לא מאומתת — וזה בכוונה: מספר שאין לו אסמכתא הוא בדיוק הסיכון.

מה למלא שם:

- **מחירון מאושר** — טווחים שהבוט רשאי לנקוב בהם, מה כלול ומה לא, הנחות מאושרות.
- **לוחות זמנים** שהמשרד מוכן לעמוד מאחורי אמירתם.
- **תנאי הזכאות בניסוח המדויק** שהמשרד עומד מאחוריו — מי מקים זכאות, אילו
  שטחים ותקופות, מה נדרש מבני זוג וילדים. אני לא מילאתי את הסעיף הזה בכוונה:
  אלה עובדות משפטיות שצריכות לצאת ממך, לא ממודל.
- **אמירות אסורות** — כבר מולא ברשימת בסיס (הבטחת תוצאה, אחוזי הצלחה, התחייבות
  ללוח זמנים, בקשת פרטי תשלום בוואטסאפ). הוסף מה שרלוונטי אצלך.

ככל שהקובץ הזה מדויק יותר — דוח ההזיות שווה יותר.

## עלות ושליטה

הרצה מלאה של 8 פרסונות × 10 תורות היא בערך 24 קריאות API לשיחות + 8 להערכה.
כדי להוזיל: `--turns 6`, או להריץ פרסונה אחת בכל פעם. אפשר גם להגדיר מודל זול
יותר לסוכן המאמן ולהשאיר מודל חזק למעריך (`TRAINER_MODEL` / `EVALUATOR_MODEL`
ב-`.env`).
