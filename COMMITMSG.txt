Stop the 24-hour window from costing leads, and stop counting ourselves as one

Two things went wrong on 10-11 October, and both of them were silent.

1. The window ate two leads.

   Free-form text may only be sent inside 24 hours of the recipient's last
   message. The last keep-alive arrived Friday 9.10 at 08:38 Israel, so the
   window shut on Saturday at 08:38. אבי (10:19) and עופר (10:52) each
   triggered a lead alert; Meta rejected both with 131047 and the alerts were
   gone — not queued, not retried, gone. sendText returned a bare boolean, so
   nothing in the code could even tell that kind of failure apart from any
   other.

   - whatsapp.sendTextResult reports the reason, windowClosed included.
   - sales/alertQueue.js holds an alert that the closed window refused and
     sends it the moment an agent writes to the bot. It is stored as events,
     so it survives a redeploy; delivery is recorded per alert, so a failed
     flush leaves the rest queued.
   - The permanent fix is a template, and this is why there were none:
     every template on the account was REJECTED with INVALID_FORMAT, because
     create-templates.js and update-templates.js both posted bodies without
     example.body_text, which Meta requires for any placeholder. Confirmed
     against the Graph API — all seven were rejected. The window has been the
     bot's only channel to the office since the day it launched.
   - src/templates.js is now the single source of truth: every template the
     code sends, with the exact parameter count of its call site and sample
     values. The test suite checks it against the code, so the three names
     that were never submitted at all (pudim_meeting_request,
     pudim_waiting_list, pudim_meetings_digest) cannot happen again.
   - sync-templates.js replaces both old scripts, which disagreed with each
     other and with the code. It fixes a rejected template by rewriting it in
     place, because deleting one needs a WABA permission this token lacks.
     The old scripts now refuse to run.
   - The hot-lead alert had no template at all. It has one now.
   - /admin/templates says which alerts can reach you outside the window, and
     what is currently held in the queue.

2. The office's own number was being sold a Romanian passport.

   0547787804 ran up 63 messages, scored 100/100, sat at the top of the
   weekly page as a hot lead nobody had called — and then crossed the
   60-message ceiling, at which point the bot handed him over to a human and
   stopped replying to him altogether.

   - config.isAgentPhone matches on the last 9 digits, so 0547787804,
     972547787804 and +972-54-778-7804 are one number.
   - An agent's message is intercepted before a session is loaded: no
     conversation, no score, no message count, no lead, no ceiling. It is
     answered with what he actually wants — the held alerts, the meetings
     waiting for his approval, and the leads waiting for his call.
   - Agent numbers are out of the funnel, the hot list, the waiting list, the
     meetings list, the weekly page, /admin/live and /admin/conversations,
     and are never followed up.
